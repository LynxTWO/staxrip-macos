# Source import cancellation research

2026-09-30. Slice 020 activated after Slice 019 hosted closure.

Code trace: WorkspaceModel.load starts an unretained Task, creates an AVURLAsset, awaits its video properties and may fall back to ffprobe. showDemo changes loadID and immediately resets the workspace, so stale results are suppressed, but neither the Task nor AVAsset loading is cancelled. The source row has a spinner and a Return to demo action, not a distinct cancellation action. Repeated replacement can leave old reads alive. Restored-path access waits are a separate observed limitation, not a proven bookmark diagnosis.

Apple documents AVAsset.cancelLoading() as cancelling pending asynchronous property requests; it should be used once that asset is no longer needed. Installed SDK headers confirm the API on the supported baseline. https://developer.apple.com/documentation/avfoundation/avasset/cancelloading()

Scratch feasibility: a custom AVAssetResourceLoader holds an in-memory resource request without supplying bytes. Calling asset.cancelLoading plus Task.cancel settles loadTracks with AVFoundationErrorDomain -11878 in about 0.001 second. Negative control with Task.cancel alone did not settle within eight seconds and the scratch harness terminated it. This demonstrates the framework cancellation seam on the development Mac; it is not a network/filesystem latency guarantee or a reproduction of restored-file permissions.

Candidate: isolate native/fallback source inspection in a cancellable service, use a cancellation handler to call asset.cancelLoading, and check Task cancellation before ffprobe fallback. Have WorkspaceModel own one active source-load task, one latest pending replacement and request identity. Replacement cancels and awaits the current worker before starting the latest pending request; cancelled/stale results cannot affect current source, player, settings, output name or errors. Expose a Cancel source loading action that retains the prior workspace and clearly reports waiting until the worker settles. Return to demo also cancels owned work. No immutable source snapshot, bookmark permission claim, saved-schema change or audio work.

Acceptance proposal: deterministic held-native-resource cancellation; fallback process cancellation and no fallback after native cancellation; controlled model success/failure/late completion/replacement tests; generated playable and fallback-format files; native cancel/load/reset walkthrough; regression/build/hosted gates. Keep existing session/file-panel captured-intent guards and source-specific reset semantics.

Additional generated FIFO feasibility: AVFoundation rejected the held MP4 FIFO with -11829 before cancellation, so it is not a native-asset cancellation fixture. FFprobe on the same owned FIFO remained pending after 0.5 seconds with the writer held open; SIGINT settled it in about 0.001 second. This can provide a visible native-app fallback-cancellation walkthrough without adding a production delay flag. It is not a promise that nonregular sources are valid export inputs; advanced export fingerprinting explicitly refuses them.

Extraction also exposes direct Int conversions of native dimensions/duration. Finite Double values at or above the Int upper boundary are not safely convertible. The source summary will use failable conversions and explicit unknown fields for unavailable/nonrepresentable metadata, without changing encoding decisions.

Native follow-up: the macOS file picker excluded the FIFO. Restoring its path from a generated session started a pending native read; Cancel displayed a truthful waiting state but did not settle, even after the writer closed. A process sample showed URLAssetWorkQueue in CoreMedia file open and the cooperative worker waiting in AVURLAsset deallocation, while the main thread remained in its event loop. Folder selection did not resolve it. This is a failed special-file native test, not successful cancellation. Amend the slice to reject empty/nonregular paths through an asynchronous metadata check before creating AVURLAsset. This avoids the reproduced unsupported path; it does not promise atomic input snapshots or bounded arbitrary filesystem latency.
