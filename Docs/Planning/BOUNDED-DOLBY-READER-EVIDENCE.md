# Bounded Dolby RPU archive reader
Version: 0.1. Date: 2026-10-03. D-093 / R-059 / Slice 049. Status: locally qualified development prerequisite; no native/runtime conversion admission.

Verified configured_behavior, local_only: Tools/DolbyMetadataAudit pins MIT libdovi 3.3.2 at 82384bc7652c6f88cb63f7f11e0315b624003fc3 and a Cargo lockfile. Escaped raw-RPU framing is scanned incrementally, with explicit input error propagation. Each record retains its full metadata, wire hash, index and delimiter offset; no duplicate suppression. CRC/syntax failure, malformed/truncated/oversize input, count/serialization bounds and I/O errors fail. A complete receipt requires EOF, an independent content recheck and stable descriptor/path size, identity and modification/change timestamps. Successful exit and complete receipt are both required; a failed flush can still fail after writing a receipt.

Verified observed_behavior: eight Rust tests passed locally, comprising one heap-accounting test and seven generated/adversarial integration tests. Profiles 5/8.1/8.4 and Level 5 offsets retain full metadata through seven chunk sizes. Identical records retain independent indices. CRC corruption, partial final record, invalid delimiters, explicit read-after-prefix failure, interrupted read retry, write/flush failure, actual source mutation after emission, FIFO and oversized sparse file refusal pass. An actual corrupt RPU requests an 80000004-byte u16 pivot allocation in the upstream parser and causes the child to fail without a completion receipt. The fixed 64 MiB Rust heap cap is not a total process-memory/RSS bound. The 512 MiB input, 64 KiB RPU, two-million-record and 2 MiB emitted JSON limits remain fixed. Core dumping is disabled for this child only.

Verified source_fact / observed_behavior, user_data scope: the optimized reader processed all 120552 records in the existing private original archive. Full per-record parsed dictionaries matched the earlier complete export, including mapping/header/display metadata and wire CRC; archive length/hash matched independently. Largest encoded RPU was 227 bytes and peak tracked Rust heap was 66076 bytes. Owner movie descriptor and current recovery file bytes stayed unchanged. It read the existing metadata archive, not the owner movie again; it performed no encoding or queue execution. These facts remain tied to the existing source/extraction receipt, tool/parser revision and private comparison artifacts.

Retained development failures: initial generation omitted required shot duration, so all generated metadata fixtures failed before parsing; adding a one-frame generated shot fixed the fixture. The first malicious-allocation fixture assumed u64 pivots, but the dependency stores u16 and requested less than the configured ceiling. Correcting that deliberately corrupt count demonstrated the real allocation refusal; no bounds/assertions were relaxed. A temporary generated-only diagnostic was removed from repository source after investigation. Cargo format, locked tests, Clippy with warnings denied and optimized build passed locally with Rust 1.98.1. The manifest's declared minimum is not a tested-platform claim.

Coverage limits: this is a complete archive reader, not proof of complete extraction or displayed-picture association. A valid prefix ending at an RPU boundary cannot reveal a missing suffix without independent expected counts/timeline. libdovi is shared with the earlier exporter; agreement is not an independent parser/reference renderer. Previous-RPU state, AV1/container parsing, matching original base/enhancement layers, picture statistics and crop/resize transforms remain future gates. No helper is bundled, no native UI behavior changed, and existing dynamic-HDR refusal remains. Distribution requires full transitive notices and separate signed packaging qualification. Dependency SPDX declarations are recorded; crc-catalog's packaged license text is missing and remains a packaging obligation.
