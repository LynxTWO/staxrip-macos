# Cancellation timer entry evidence

D184 adds one bounded test-only discriminator for the existing M5 cancellation harness. The exact D179 hosted run reported `rendererCancel` with `gate.passed == false`; its source ordering supports expiry winning before completion acquired the gate lock, but did not show whether the timer entry marker had executed. The separate Rendering missing-notification failure is not automatically the same cause.

The timer now records a Boolean under a separate lock before attempting gate completion. Expiry freezes that marker with the authoritative expired transition. Late entry cannot rewrite the frozen fact, observe live work, notify or request cancellation after expiry. Completed remains authoritative. Fixed categorical records at existing recovery and joined-settlement boundaries contain only context, target, resolution, entry, entry-at-expiry, live observation and test-cancellation state. `live=none` means no completion observation occurred.

The same 20 ms delay, 10-second escape, under-five-second bound, notification requirement and source/publication/cleanup assertions remain. Missing notification still cancels and joins the exact task and retains its holder/task/result before failing. No product, ChapterPlan queue, fixture cleanup or resource-release policy changes.

One deterministic test exercises marker-before-expiry, marker-after-expiry, suppression of late completion effects and completed-winner authority. It is not a real timer-expiry or concurrent stress test. Independent review is source-only. The marker identifies its protected write, not callback first instruction, queue starvation or gate-lock contention. Added instrumentation changes overhead; timing equivalence is not claimed. Stream yield/termination provenance remains outside this diagnostic.
