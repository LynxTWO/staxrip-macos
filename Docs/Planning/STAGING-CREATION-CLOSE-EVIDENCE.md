## Concrete behavior

Creation owns opened parent/directory numbers before later admission can throw.
On refusal, it consumes each number before one actual close, accumulates results
and attempts both owned roles even when the first reports uncertainty. No retry
or post-return number absence is used as close evidence. Successful transfer
leaves those pins with the existing stage owner; its later terminal settlement
remains unqualified.

Fresh descriptor/path observations bind the opened stage and parent before
transfer, including after the DEBUG generated boundary. Creation failure records
whether mkdir actually succeeded and whether descriptor/path identity was
established. Those are observations during this attempt, not current immutable
identity, producer provenance or authority to adopt/remove a path. Rollback
never removes a created directory. A created-but-untransferred directory requires
review even if the actual closes succeeded; unsafe identity is never adopted.
Before creation, normal checked rollback preserves the original refusal. Reported
or actual close uncertainty identifies the parent and explicitly says no stage
was created. D105/D134 preserve these concrete facts/locators, original causes,
source-close priority and needed access through dropped-error retained review.
Activity expiry only expires energy; it does not release grants or authorize
cleanup. No publication occurs on any creation refusal.
