# P8.1 output proof

A dedicated M2 verifier now joins native packet framing, exact timing, full Dolby metadata and complete decoded-frame evidence for the bounded P7-to-P8.1 contract. P8.1 conversion remains unavailable in the app. The missing production mux and complete source-to-result journey remain acceptance gaps.

The new checked output role requires the exact admitted P8/L6/CCID1 declaration, one RPU per packet, no enhancement NALs and no non-base-layer picture NALs. It preserves in-band parameter sets and compares the ordered retained base-layer bytes with the source. Existing HDR10 output still rejects every Dolby declaration and RPU. Original source defaults remain unchanged. Output inspection cannot select the legacy unchecked reader path.

Every full-metadata packet digest is compared with an independent native whole-packet digest, including signed nanosecond PTS and size. Both packet receipts bind the explicit FFprobe PTS/DTS/duration sequence. The combined proof requires matching source/output metadata roles, final fingerprints, byte counts, RPU/enhancement census, configuration and default duration. The source's expected normalized metadata must equal the output's complete normalized metadata. Strictly increasing native PTS bind every decoded frame; static HDR, topleft chroma and complete decoded pixel hashes must agree. Reordered or ambiguous picture association still refuses. This uses the same installed decoder and libdovi lineage, not independent Dolby rendering.

Three new synthetic framing and joined-receipt tests cover valid admission plus declaration, RPU/layer, metadata association, fingerprint, timing, pixel and picture-PTS corruption, and output-role refusal before tool admission. Their fabricated receipts are not decodable Dolby proof. A separate private host built from all 94 current product sources read the retained generated eight-picture pair through actual checked acquisition, full helper metadata, packet timing, complete decoded frames and final fingerprint rechecks. It passed with eight source/output RPUs, twenty source enhancement NALs and zero output enhancement NALs; both inputs remained unchanged. The initial host failed because checked inspection still rechecked every file as P7. That failure is retained; the explicit checked output role corrected the source-backed defect and the subsequent host passed. Independent review was source-only.

A separate generated installed-FFmpeg split/recompression trial removed enhancement NALs but retained P7/MEL metadata and a P7 declaration. It was rejected as a P8.1 route. No retagging or production admission follows that trial.

This verifier acquires no cleanup, publication or access-release authority. Its future caller must hold the concrete admitted source/output resources through every helper and final observation and retain them on shared uncertainty. No new UI, production P8.1 mux, queue, publication, cancellation/drop/expiry execution, release signing or milestone exit is claimed. All M1-M5 remain open.
